## 🚀 FUTURE ARCHITECTURE: STOCK SCREENER SYSTEM

### New Requirements
1. **Periodic Scanning:** Every 15 min scan all tracked stocks

3. **Confidence Scoring:** Each signal gets a confidence % (0-100)
4. **Watchlist:** Track screened stocks with signals
5. **Signal Aggregation:** Combine signals from multiple strategies
6. **Auto-Execution:** Optionally auto-execute high-confidence signals

#### 5. Background Task Scheduler
```python
# backend/services/background_tasks.py

class BackgroundTaskScheduler:
    """
    Manages periodic market scanning
    Uses APScheduler or similar
    """
    
    def __init__(self, scanner: MarketScannerService):
        self.scanner = scanner
        self.scheduler = APScheduler()
    
    def start(self):
        """Start 15-minute scan loop"""
        self.scheduler.add_job(
            func=self.scanner.scan_market,
            trigger="interval",
            minutes=15,
            id="market_scan_15min"
        )
        self.scheduler.start()
```

## 🔧 KEY DESIGN DECISIONS

### 1. Parallel Strategy Execution
**Why?** Multiple strategies need to run simultaneously to stay within 15-min window
**How?** `asyncio.gather()` or `ThreadPoolExecutor` for CPU-bound strategies
**Trade-off:** Thread safety, resource usage

### 2. Confidence Aggregation Methods
```python
# Average: Simple mean
confidence = mean([0.75, 0.60, 0.45]) = 0.60

# Weighted: Strategies have different weights
confidence = (0.75 * 0.4 + 0.60 * 0.4 + 0.45 * 0.2) = 0.615

# Voting: Only count if 50%+ agree
if sum(1 for s in signals if s.side == 'long') >= len(signals) * 0.5:
    confidence = mean([0.75, 0.60, 0.45])
else:
    confidence = None  # conflicting signals

# Consensus: Require agreement from main strategies
if all(s.side == 'long' for s in signals[:2]):  # MA + RSI agree
    confidence = mean([s.confidence for s in signals])
```

**Recommendation:** Start with **weighted** (allows tuning which strategies matter most)

### 3. Signal Deduplication
Don't store duplicate signals for the same symbol+side+timeframe
Strategy: Hash(symbol, side, timestamp_rounded_to_5min) as signal key

### 4. Auto-Execution Safeguards
- Min confidence threshold (e.g., 65%)
- Max trades per day cap
- No consecutive signals on same symbol within X minutes
- Manual override available
- Audit log for compliance

### 5. Database Indexes
Critical indexes for performance:
```sql
CREATE INDEX idx_signals_symbol_time ON signals(symbol, emitted_at DESC);
CREATE INDEX idx_positions_symbol_status ON positions(symbol, status);
CREATE INDEX idx_watchlist_enabled ON watchlist(enabled);
CREATE INDEX idx_candles_symbol_time ON candles(symbol, timeframe, close_time DESC);
```

## 📋 DEPENDENCIES TO RESEARCH

- **Async Task Scheduling:** APScheduler, Celery, or FastAPI BackgroundTasks?
  - APScheduler: Simple, in-process, good for single-server deployment
  - Celery: Overkill unless you scale to multiple workers
  - BackgroundTasks: Built into FastAPI, lightweight
  
- **Parallel Execution:** asyncio.gather vs ThreadPoolExecutor?
  - asyncio: For I/O-bound (API calls)
  - ThreadPool: For CPU-bound (strategy calculations)
  - Recommendation: **asyncio for feeds, ThreadPool for strategies**

- **Strategy Loading:** Dynamic strategy registration?
  - Registry pattern: `STRATEGY_REGISTRY = {'MA': MAStrategy, 'RSI': RSIStrategy}`
  - Allows adding strategies without code changes
  - Load from config file or database

- **Rate Limiting:** API rate limits for feeds?
  - Binance: 1200 requests/min
  - Zerodha: Check their limits
  - Strategy: Cache candles, batch requests, use WebSocket for real-time
